## 为什么之前的“DeepSeek 校验 200”与失败不矛盾
- 启动校验 `DeepSeekAdapter.verify_model()` 只调用 `GET {base_url}/models`（模型列表），
  该请求不涉及推理计费；密钥有效、模型在列表中时会返回 200。
- 需求转换调用 `POST {base_url}/responses`，需要实际余额/额度；余额不足时供应商返回 402。
- 因此旧实现把 401/402/403 统一映射为 `AI_AUTH_OR_QUOTA / provider rejected credentials`，
  把“余额不足”误报成“凭据被拒”，这是诊断被误导的直接原因。

## 结论
- 失败不是 API Key 无效、不是模型名错误、不是 Base URL 错误，也不是 Compose 注入缺失。
- 失败时供应商返回 HTTP 402 Payment Required（余额/额度不足）；当前账户余额为正，
  同一套配置的真实推理请求与完整 P1 转换均已成功。
- 余额从失败时的状态变为当前 8.49 CNY 的具体时间点无法由供应商 API 证明；
  需在 DeepSeek 控制台核对充值/扣费记录。若未充值，应按供应商计费异常处理。
