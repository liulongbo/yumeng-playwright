## 1. 修复内容

### 1.1 行为

Collection Worker 启动时，在 `register_worker_instance()` 之后、启动 Temporal Worker 之前，执行一次
`reconcile_quarantined_unit()`：

1. 仅当单元 `state='QUARANTINED'` 时继续；
2. 若存在活跃租约、`OPEN/ACKNOWLEDGED` 验证事件或 `REQUESTED/ACTIVE/VERIFYING` 接管，**不回收**；
3. 调用 `confirm_local_browser_stopped()`（项目 Profile `flock` + Chromium SingletonLock/PID；Windows 为 `msvcrt` + `lockfile`）；
4. 证明通过后调用既有 `recover_stopped_unit()`，actor 为 `collection-worker:<worker_instance_id>`，写 `audit_logs`；
5. 证明失败或回收被拒绝时只记录 warning，单元保持隔离，Worker 继续服务队列（不阻塞启动）。

不新增表/迁移，不改变 `acquire()` 的 fail-closed 语义；不按 `failure_reason` 字符串白名单过滤
（`QUARANTINED` 只由 expired-owner 或 unconfirmed-browser 产生；若未来引入人工隔离，应新增独立标记）。

## 5. 残余问题与边界

1. **`completed_at` 仍为 12:17:58（首次网络失败时间）**，而状态在 12:28:05 变为 `PARTIAL_COMPLETED`。这是既有
   `TERMINAL_COMPLETED_AT_CLAUSE` 行为（只写一次终态时间，后续重试不覆盖），不是隔离修复引入；与 LIVE-01
   记录过的 `completed_at` 问题一致。页面「完成时间 12:17 / 最近更新 12:28」会不一致。
2. **`featured_complete_count=0`、`profile_complete_count=0`**：任务进入 `PARTIAL_COMPLETED / PROFILE_SCOPE_INCOMPLETE`，
   2 位达人快照已发布，但主页资料/精选完整性未全部满足；这是真实采集完整度，不是隔离错误。
3. **封面 6/6 FAILED、`media_objects=0`**：单元配置的封面存储为 S3 `http://100.86.124.51:9000`，本机当前未完成封面入库；
   页面显示「封面加载失败」。与隔离修复无关，但影响验收观感；需另立封面/存储任务。
4. **`execution_units.profile_ref` 仍指向旧 checkout**；本轮未改数据绑定。
5. **launchd `com.yumeng.xingtu.collection-worker` 仍加载但脚本不存在**；本轮未改 launchd。
6. **Windows 与 F10 真实路径未验收**；不能宣称双平台/接管恢复已通过。
