## 1. 修复前的问题及根因

**问题（ISSUE-001，P0）**：一次 target=2 的真实采集中，两位达人的 **4 组精选集合全部 `NOT_ATTEMPTED`**，`featured_collections` 0 行、封面 0 个；任务以"部分完成"收口，且 `failed_count=2` 与 `valid_count=2` 并存。

**根因（已用只读 DOM 探针 2/2 达人复现）**：精选路径会**重载同一达人主页**，此时平台 SPA 正在 hydration，`div.author-info span.copy-text` 存在约 **45–60 ms 只渲染空文本**的窗口；该元素**存在且唯一**，因此 `read_locator` 的位置检查通过，而它**只拒绝 `value is None`**，空字符串被当作一次成功的身份读取返回；`verify_identity` 随即比较 `'' != platform_creator_id` → 抛 `CREATOR_INVALID: IDENTITY_MISMATCH`。

**放大后果**：`collect_featured_collections` 对非 `MODULE_COLLECTION_FAILED` 的异常直接上抛 → ①第二个精选集合也不再尝试；②**零 `FeaturedCollectionObservation` 落库**；③`_collect_once` 捕获后保留 `valid=True` 只把状态置 `failed`。

**为什么资料阶段不失败**：资料阶段从业务页进入、应用外壳已预热，身份文本早于 `check_session` 返回即已填充，竞态被赢下。

## 3. A / C1 实现说明

### 3.1 A：身份读取竞态

**兼容性优先**：`read_locator` 的默认行为**完全不变**（空串仍视为合法读取），只有显式传入 `require_non_empty=True` 时才把**空白值**判为 `UNREADABLE_VALUE`（与"节点缺失"的 `MISSING_SOURCE` 区分）。经前置调查：全场只有 3 个调用点，`session.identity` **只被 `verify_identity` 读取**；已核验契约中 `kind: dom` 字段来源为 **0 个**，因此其他调用方（`readback`、`source`）行为零变化。

**有界等待与稳定性关系（按用户要求明确）**：

```
等待上限 = identity_read_cap_seconds = 5.0s   # 约束"完整身份读取及确认过程"
轮询间隔 = identity_poll_seconds     = 0.1s
loop:
  读身份（require_non_empty=True）
  ├─ == expected            → 立即通过（期望值是已知常量，瞬态不可能等于它，故无需二次确认，正常路径只读 1 次、零额外延迟）
  ├─ 空白 / 读取失败         → 继续轮询（空白永远不是有效值）
  ├─ 非空但 != expected      → 记录该值；**再读一次**；两次相同 → IDENTITY_MISMATCH
  │                            第二次回到 expected → 通过（瞬态错值不构成"错误达人"）
  └─ 超过上限               → IDENTITY_UNREADABLE
```

- "两次一致"**只用于非空但不符合预期的可疑路径**，避免把瞬态错值误报为 `IDENTITY_MISMATCH`；正常路径不付这个成本。
- 整个读取+确认过程由 `asyncio.wait_for` 统一硬上限，**单次读取自身的等待也包含在 5s 内**，不会出现"单次读取超时导致总耗时远超预期"。
- `wait_for` 只在自身超时抛出 `TimeoutError`；**任务取消（`CancelledError`）照常向上传播**，未触碰心跳/租约/会话安全机制。
- 超时映射为既有错误码 `PLATFORM_PAGE_CHANGED: IDENTITY_UNREADABLE`（交由既有达人级 **最多 3 次**有界重试处理，未新增重试层级）。
- **未跳过校验、未忽略错误、未放宽一致性**：稳定非空但不匹配仍严格返回 `IDENTITY_MISMATCH`。

### 3.2 C1：精选故障隔离

把原先的 `if exc.code != "MODULE_COLLECTION_FAILED": raise` 换成**显式白名单** `featured_spec_local_reason(error)`：

| 归类 | 条件 | 处理 |
|---|---|---|
| **本精选局部失败** | `MODULE_COLLECTION_FAILED`（该精选自身已登记请求/卡片读取失败） | 生成 `_featured_failure` 观测（`status=FAILED` + `failure_reason`），**继续下一个精选** |
| **本精选局部失败（C1 新增）** | `PLATFORM_PAGE_CHANGED` 且 `reason == "PAGE_READY_TIMEOUT"` | 同上 |
| **仍然中止** | 会话（`ACCOUNT_LOGIN_REQUIRED`/`ACCOUNT_MISMATCH`/`PLATFORM_SECURITY_CHALLENGE`）、租约（`RESOURCE_UNAVAILABLE`/`LEASE_LOST`/`SESSION_INDETERMINATE`）、身份（`CREATOR_INVALID`/`IDENTITY_UNREADABLE`）、以及任何**未列入**的 `PLATFORM_PAGE_CHANGED` | 原样上抛，不降级 |

**C1 前置确认**：`PAGE_READY_TIMEOUT` 全场**只有一个生产者**（`wait_ready`，且只在调用方自己的 `ready` 选择器未出现时抛出），因此在精选迭代内它**只可能**描述"本精选页面未就绪"。按用户指示，**未扩展**处理 `RESPONSE_CONTENT_TYPE`/`RESPONSE_SCHEMA_MISMATCH`/`RESPONSE_TOO_LARGE`。
