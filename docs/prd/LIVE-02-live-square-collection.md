# 直播达人采集扩展 PRD（巨量星图 / 磁力聚星）

状态：已批准（2026-11-04），第二阶段开发中  
版本：v0.1（2026-11-04）  
关联：[LIVE-02 任务卡](../tasks/LIVE-02.md)、[真实页面调查证据](../evidence/LIVE-02-live-square-investigation.md)、[技术方案](../design/LIVE-02-live-square-technical-design.md)、[测试用例](../evidence/LIVE-02-test-cases.md)、[影响分析](../design/LIVE-02-compatibility-impact.md)

## 1. 项目背景与现状

本项目是 MCN 媒介人员使用的达人数据采集与管理系统，当前已支持：

- 巨量星图、磁力聚星两个平台的**短视频广场**达人采集；
- 统一任务中心、Temporal 调度、双平台专属执行单元（`unit-local-mac-02` / `unit-local-mac-03-juxing`）；
- 达人库、任务内达人快照、短视频达人详情；
- 星图达人手动更新与定时更新（聚星手动更新/定时更新当前不支持）；
- 采集、失败重试、继续采集、补采缺失字段、取消等任务操作。

现有短视频能力已通过真实平台验证，是本次开发必须保护的基线。

本次要新增的是：**同一平台内，用户可以选择「短视频广场」或「直播广场」场景，采集、存储、查看和更新直播达人资料。** 短视频与直播是并存关系，不是替换关系。

## 2. 本次新增功能的业务目的

1. 媒介人员寻找直播达人时，不必离开本系统去平台手工筛选、抄录。
2. 直播数据（观看、在线、互动、带货、报价等）与短视频数据分开保存、分开更新、分开查看，避免指标混用。
3. 同一达人既有短视频又有直播数据时，能识别为同一平台身份，但两类数据互不覆盖。
4. 所有直播采集/更新仍然进入现有任务中心和执行单元，不新增第二套任务系统或执行资源。

## 3. 目标用户与使用场景

| 用户 | 场景 | 期望结果 |
|---|---|---|
| 媒介人员 | 在巨量星图找直播达人 | 选择「巨量星图 → 直播广场」，按昵称/抖音号/星图ID检索，填目标数，提交任务；任务中心看到进度；达人库直播场景看到结果 |
| 媒介人员 | 在磁力聚星找直播达人 | 选择「磁力聚星 → 直播广场」，按快手ID/昵称检索，填目标数，提交；任务中心/达人库同样可查 |
| 媒介人员 | 复盘直播达人 | 打开直播详情，查看近期直播场次、观看、在线、互动、带货、报价及数据来源/时间 |
| 媒介人员 | 更新直播资料 | 在达人详情点击「手动更新直播资料」，只刷新直播数据；短视频数据不变 |
| 媒介人员 | 同一达人两套资料 | 在详情中切换「短视频资料 / 直播资料」，分别查看与更新 |
| 媒介人员 | 跨平台同名/同ID | 星图与聚星互不合并；各自保留平台身份 |

## 4. 现有业务流程与新增流程对比

### 4.1 现有短视频流程

选择平台 → 填写短视频筛选条件 → 提交 → P1 转换 → 任务中心 → 平台执行单元 → 短视频广场检索 → 达人主页采集 → 短视频快照/达人库 → 查看/更新。

### 4.2 新增直播流程（推荐首版）

选择平台 → 选择场景「直播广场」 → 填写关键词/ID 与目标数（首版不开放直播筛选器） → 提交 → P1 转换 → 任务中心（标记直播场景） → 同一平台执行单元 → 直播广场检索 → 直播详情采集 → 直播快照 + 直播当前资料 → 达人库直播场景 → 直播详情 → 手动更新直播资料。

### 4.3 关键差异

| 维度 | 短视频 | 直播（本次新增） |
|---|---|---|
| 入口 | 短视频广场 | 直播广场；独立 URL/路由 |
| 筛选 | 现有筛选能力不变 | 首版只开放已核验的关键词/ID + 目标数；筛选器清单见附录，后续任务实现 |
| 列表字段 | 现有 | 平台直播列表字段（两平台不同） |
| 详情 | 短视频主页 | 直播专属详情（星图「抖音直播主页」/聚星「达人直播主页」） |
| 数据 | 短视频快照/current | 直播快照/直播 current，独立存储 |
| 更新 | 星图手动/定时；聚星不支持 | 直播手动更新（两平台）；**不做定时** |
| 身份 | `(platform, platform_creator_id)` | 相同身份；数据分离 |

## 5. 本次功能范围

1. 新增「直播广场」场景选择（两平台）。
2. 新增直播采集任务：关键词/ID + 目标数，进入现有任务中心。
3. 直播数据独立存储，与短视频数据隔离，兼容现有达人主数据/快照体系。
4. 直播达人库列表与直播详情页。
5. 达人详情增加独立的直播更新入口。
6. 任务中心增加场景识别/筛选/展示。
7. 复用现有执行单元与互斥机制。
8. 真实浏览器端到端验收与短视频回归。

## 6. 明确不开发

- 不新增任务中心、执行单元、队列、Chrome/Profile。
- 不改变短视频采集、筛选、快照、详情、更新与定时更新行为。
- 不开发直播**筛选器**（首版只做关键词/ID + 目标数；本次只产出筛选字段清单，供后续任务）。
- 不做直播定时更新，不把直播达人加入现有定时更新。
- 不做直播榜单、直播分析逐场明细、受众画像深度分析（详情页只展示已核验的概览字段；标签页字段待后续）。
- 不采集联系方式（微信/电话/邮箱），不采集平台不允许的数据。
- 不做跨平台身份合并、不做跨平台同名匹配。
- 不做批量导入/导出、评分、商单管理。
- 不重构现有数据库/任务中心/执行单元。

## 7. 功能清单与功能描述

### F-L1 场景选择

- 新建任务页在平台选择之后显示「采集场景」：短视频广场 / 直播广场。
- 短视频为默认；直播在未启用/未验证时禁用并显示原因。
- 切换场景时表单、筛选条件、幂等键、目标数默认值按场景重置；不得把短视频条件带入直播任务。

### F-L2 直播任务创建

- 直播表单只显示当前平台**已核验**的字段：
  - 巨量星图：昵称/抖音号/星图ID（必填之一）、目标达人数量。
  - 磁力聚星：快手ID/昵称（必填之一）、目标达人数量。
- 首版要求至少填写一个关键词/ID，不允许空条件采集（避免平台默认条件/全量列表带来的口径问题）。
- 目标数默认 20，允许 1—70（两平台统一）；超过 70 前端禁止提交、后端也必须拒绝；实际可发现数量受平台分页能力约束，达到边界时任务为部分完成并说明原因，不谎报平台耗尽。
- 直播 70 位为本次新增能力，**不调整现有短视频上限、分页逻辑和有效达人判定口径**；短视频既有 70 位能力保持。
- 星图直播默认条件「达人报价：品牌营销专场(按小时)」必须在采集开始时清空；清空动作和结果需可回读（阶段二验证）。
- 提交后返回任务详情；重复点击/重试不创建第二个任务（沿用现有幂等）。

### F-L3 任务中心

- 任务列表/详情显示平台 + 场景（如「巨量星图 · 直播广场」）。
- 任务中心支持按场景筛选；短视频默认视图不变。
- 直播任务使用现有状态机、计数、取消/继续/重试/补采语义；计数文案区分「有效达人/资料完整/精选」等，直播不显示短视频精选计数。
- 失败原因可读，不把「找不到元素」当「平台无数据」。

### F-L4 直播数据入库

- 同一平台身份只建一条 `platform_creators` 记录；直播快照带场景标记。
- 直播当前资料写入直播专用 current 表；**不得写入短视频 current 表或 `platform_creators.projection`**。
- 每个字段保存：值、原文、单位、统计周期、来源、观测时间、状态（COLLECTED/NO_DATA/NO_PERMISSION/FAILED/NOT_ATTEMPTED）。
- 真实零值与缺失分开；平台返回空对象/空数组时是 NO_DATA，不展示为 0。
- 同一次任务重复采集同一达人不产生重复身份；快照按既有追加不可变规则保存。

### F-L5 达人库直播视图

- 达人库增加「业务数据」选择：短视频 / 直播；默认短视频，现有页面不变。
- 直播列表按平台展示；字段按平台原生口径，不做跨平台强行统一。
- 列表至少展示：头像/昵称、平台、直播关键指标、报价（有则显示）、最近更新时间、数据完整度。
- 同一达人两场景都有数据时，列表分别出现；进入详情后可切换。
- 直播列表筛选首版只提供平台、完整度、粉丝数/更新时间等已核验维度；不做未验证的直播筛选。

### F-L6 直播达人详情页

- 独立路由/页面，延续现有达人详情视觉与信息层级。
- 基础资料：头像、昵称、平台、平台ID、性别、地域、粉丝数、达人类型/内容标签、MCN/机构（平台提供时）。
- 直播表现（按平台）：
  - 巨量星图：近期直播场次、平均观看人数、平均观看人次、ACU、PCU、粉丝观看占比、场均涨粉数、场均评论率、场均点赞率、平均看播时长、场均互动率（响应有但页面未列时标注来源）。
  - 磁力聚星：预期观看人数、最高在线人数、预期CPM、周均直播场次、直播互动率、平均观看人数、场均点赞；不把视频口径的 `photo*`/`queryCommerceInfo` 字段放进直播模块。
- 带货/转化表现（平台提供时）：星图带货商品数/场均GMV/客单价/GPM/CTR/CVR；聚星带货直播场次/观看中位数/最高在线中位数/商品数。空值显示「暂无数据」，不显示 0。
- 报价：按平台原生合作形式展示（星图品牌营销/电商专场/拼场；聚星按小时/按天/按商品）。
- 数据来源：显示「来源：直播详情 / 采集时间 / 统计周期」，可展开字段级来源。
- 最近采集/更新：显示最近成功更新时间、最近任务状态、失败原因（若有）。
- 操作：直播手动更新；若同时有短视频资料，提供「查看短视频资料」切换。
- 详情页不得展示联系方式。

### F-L7 手动更新直播资料

- 在达人详情提供独立按钮「手动更新直播资料」。
- 点击后创建直播 `manual_update` 根任务，进入现有任务中心；只采集该达人的直播资料，不做搜索、不新增达人。
- 仅对已有直播数据的达人显示该按钮（首版）；同一达人已有在途直播更新时，按钮显示「更新进行中」并复用该任务，不重复创建。
- 更新失败不清空已有直播数据；成功后写新的直播快照/current。
- 短视频更新按钮保持原行为；两按钮互不影响。
- 直播更新不写 `creator_update_schedule`，不进入定时更新池。

### F-L8 兼容与默认值

- 所有现有 API 不传场景时默认短视频；旧任务、旧快照、旧详情保持原语义。
- 直播功能通过配置开关控制；未启用时场景选项禁用，不创建直播任务，不静默回退。
- 聚星短视频手动更新现状（不支持）保持不变；本次不补。

## 8. 前端页面与交互设计建议

### 8.1 新建任务页

```text
[平台]  巨量星图 | 磁力聚星
[场景]  短视频广场 | 直播广场     ← 新增，短视频默认
[直播条件]（仅直播）
  昵称/抖音号/星图ID（星图） 或 快手ID/昵称（聚星）
  目标达人数量（默认 20，1—70）
[提交]  idempotency key 按平台+场景+表单生成
```

- 场景切换时清空另一场景的条件，避免串场景。
- 直播首版不显示短视频筛选区；显示提示「直播筛选能力正在调研，本版仅支持关键词/ID + 目标数」。
- 能力版本、目标上限以服务端返回为准；直播上限固定 70，不能只改前端输入框。

### 8.2 任务中心

- 行信息：平台 · 场景 · 任务类型 · 创建人/时间。
- 筛选：平台、场景、状态、类型、日期；场景筛选默认全部，短视频默认视图不变。
- 任务详情：场景标识、计数、失败原因、操作按钮；直播隐藏精选计数。
- 空状态/错误态沿用现有组件。

### 8.3 达人库

- 顶部增加「业务数据：短视频 / 直播」切换；平台选择保持。
- 直播列表行：头像/昵称、平台、粉丝数、直播关键指标（按平台）、报价、完整度、更新时间。
- 直播列表不显示短视频专属指标；短视频列表不显示直播指标。
- 同一达人两场景都有数据时，详情页提供「短视频资料 / 直播资料」切换；列表分别进入对应场景。

### 8.4 直播详情

建议版式（沿用现有 `panel/section` 风格）：

```text
[返回达人库]  昵称 · 平台 · 直播场景      [手动更新直播资料] [查看短视频资料]
基础信息（头像/ID/性别/地域/粉丝/类型/机构）
直播表现（平台原生指标，注明 30 天/来源）
带货与转化（有则显示，无则「暂无数据」）
报价（平台原生合作形式）
数据来源与最近更新（观测时间/字段来源/任务状态）
[右侧/底部] 最近更新历史（可选，首版可只显示最近一次）
```

- 不新增设计系统；复用现有颜色、卡片、标签、状态组件。
- 移动端/窄屏沿用现有响应式规则。

## 9. 数据字段与存储要求

### 9.1 字段原则

- 以真实页面/响应为准；未验证字段不展示、不存储。
- 每个字段保留平台原文、单位、周期、来源、观测时间。
- 同名不同义不合并；不同平台字段不强行同表同列。
- 平台空对象/空数组/`-` → `NO_DATA`；平台返回真实 0 → 数值 0。
- 不采集联系方式、Cookie、令牌、完整响应正文。

### 9.2 直播字段清单（首版建议）

**巨量星图（详情概览已核验）**

| 业务分组 | 字段 |
|---|---|
| 身份 | 星图ID、昵称、头像、性别、地域、粉丝数、内容类型/标签 |
| 直播表现 | 近期直播场次、平均观看人数、平均观看人次、ACU、PCU、粉丝观看占比、场均涨粉数、场均评论率、场均点赞率、平均看播时长、场均互动率 |
| 带货 | 带货商品数、场均GMV、带货商品客单价、GPM |
| 转化 | 场均CTR、小手柄/小雪花/小风车 CTR、小手柄 CVR（平台有数据时） |
| 报价 | 品牌营销专场（按小时）、电商带货专场（按小时）、电商带货拼场（按商品） |
| 来源 | 观测时间、统计周期（近30天）、列表/详情来源、字段状态 |

**磁力聚星（详情概览已核验）**

| 业务分组 | 字段 |
|---|---|
| 身份 | 快手ID（userId）、starId、昵称、头像、性别、地域、粉丝数、达人类型、所属行业、所属机构 |
| 直播表现 | 预期观看人数、最高在线人数、预期CPM、周均直播场次、直播互动率、平均观看人数、场均点赞 |
| 带货 | 带货直播场次、观看人数中位数、最高在线人数中位数、带货商品数（平台有数据时） |
| 达人指数 | 综合指数、同行业/同粉丝段排名（平台提供时） |
| 报价 | 按小时、按天、按商品（拼场直播） |
| 来源 | 观测时间、统计周期（近30天）、列表/详情来源、字段状态 |

> 完整逐字段清单（含路径、单位、是否可获取）见[调查证据](../evidence/LIVE-02-live-square-investigation.md)与技术方案附录；本文只列首版展示范围。

### 9.3 存储要求（产品视角）

- 直播资料单独保存，不覆盖短视频资料。
- 同一平台身份只保留一条达人身份；直播与短视频共享身份。
- 直播快照可追溯（每次更新保留历史），当前资料指向最近一次有效直播观测。
- 直播列表/详情读取直播独立数据，不读短视频 current 表。
- 迁移必须增量、可回滚；不删除/重写历史数据。
- 直播定时更新暂不启用；数据结构预留未来扩展，但不引入调度逻辑。

## 10. 任务中心及手动更新规则

| 规则 | 要求 |
|---|---|
| 统一任务中心 | 直播任务进入现有任务中心；不新增第二套 |
| 任务类型 | 采集任务、手动更新任务；直播永不使用定时更新 |
| 场景标识 | 任务记录平台 + 场景；列表/详情/筛选可见 |
| 执行单元 | 星图直播 → `unit-local-mac-02`；聚星直播 → `unit-local-mac-03-juxing`；不新增单元 |
| 并发/互斥 | 同平台直播与短视频共用单元、串行；跨平台并行保持 |
| 在途/重复 | 沿用现有重复提交/在途任务反馈；直播更新同一达人只保留一个在途任务 |
| 失败/重试 | 沿用现有失败分类、重试/继续/取消；失败不清空已有直播数据 |
| 定时更新 | 直播不创建 schedule 行，不进入 update-scheduler；短视频定时更新不受影响 |

## 11. 异常场景与边界处理

| 场景 | 用户可见结果 | 系统行为 |
|---|---|---|
| 平台登录失效 | 任务等待登录/失败，提示原因 | 不绕过登录；不静默重试 |
| 安全验证 | 任务等待人工验证/接管 | 沿用现有挑战流程 |
| 无直播权限 | 场景不可用/任务失败，提示无权限 | 不伪造数据，不切换到其他账号 |
| 平台页面变化 | 任务失败/部分完成，带失败原因 | 保存脱敏证据，不猜测字段 |
| 全部为空/无数据 | 显示「暂无数据」 | NO_DATA，不显示 0 |
| 部分字段失败 | 任务部分完成，详情标记缺失 | 保留已采集字段；失败不清空旧值 |
| 目标数未达 | 部分完成，显示已有效/目标/原因 | 不谎报平台耗尽 |
| 翻页边界 | 部分完成，保留游标 | 达到已验证边界停止，不重复请求 |
| 同一达人重复采集 | 不重复建身份；追加新快照 | 按平台身份去重 |
| 重复点击更新 | 复用/提示在途任务 | 幂等 + 在途检查 |
| 同达人两场景 | 详情可切换；各自更新 | 数据隔离 |
| 跨平台同名/同ID | 分开显示 | 平台身份隔离 |
| 短视频回归 | 原页面/任务/更新不变 | 默认场景短视频；旧数据不动 |
