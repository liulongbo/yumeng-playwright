## 目标与范围

在**不改采集流程、不改数据库结构、不改快照与字段观测选择规则**的前提下，按用户本轮要求完成四项调整：

1. **任务一 · 移除「达人概览」**：从达人详情页移除该 Tab 入口与其可见内容；最终只保留五个 Tab，顺序为
   商业能力 → 创作能力 → 履约能力 → 连接用户 → 报价与历史；默认选中 **商业能力**；旧标识不得导致空白页或报错。
2. **任务二 · 最新视频表现图表优化**：每根柱子默认可见地展示该视频**真实播放量（万为单位）**；
   X 轴由数组序号改为该视频**真实发布时间**；柱子 Hover 展示该视频**封面/标题/播放量**浮层；
   点击柱子/Tooltip 在新标签页打开该视频的**真实抖音链接**。
3. **任务三 · 下方作品区域**：展示真实封面（无可用封面地址时按现有占位方式降级）并支持点击跳转。
4. **任务四 · 移除「视频表现口径对照」**模块的页面展示。

包含：`CreatorProfile` 章节配置与默认态、`CreationPanel` 的结构、新视频图表/作品组件、展示层格式化、
局部样式、针对性前端测试、真实浏览器验收与文档回写。

不包含：采集契约与解析（Parser/Adapter）、Scheduler/Queue/Worker、登录与会话、数据库 Schema 与迁移、
数据回填、`root_tasks`/快照结构、其他页面与其他章节的重构。**本轮未执行任何数据库 Schema 修改、迁移或数据回填。**

### 开发前调研结论（2026-10-15）

- 当前实现：`frontend/src/profile/CreatorProfile.tsx` 的 `chapters` 数组含 6 个 key（`overview` 为默认），

  **全仓库无任何 import**（死代码），本轮不动它，避免越界重构。
- 视频数据链路：`creator_snapshots.payload.modules.creation.fields[]` 中
  `recent_video_performance` / `recent_xingtu_video_performance` 的 `value.data` 为**对象数组**，

## 交接信息

### 阻塞与缺口

1. **视频封面无法渲染（数据侧缺口，需用户决策）**：JSONB 中 `item_cover` / `head_image_uri` 是**平台对象存储
   的不透明 key**（如 `tos-cn-i-0813c000-ce/ownaEMiVAPe6AynMEABAIsZ6e81wlEDAAkipfP`），不是可直接渲染的
   HTTPS 地址；全库 1845 条非空封面中 **0 条**是完整 URL，也从未入库对象存储。精选作品卡片之所以能显示封面，
   是因为其契约字段 `cover` 返回的是 `p3-star-fe-sign.byteimg.com` 等**已签名完整外链**，由 `CoverPipeline`
   受控下载入库；最近视频记录**没有任何等价字段**。
   本轮选择：不构造未经验证的 CDN 地址（不猜域名、不越界改采集/白名单），封面按现有占位方式降级并如实标注。
   **影响**：CRE-14 以「降级正确」通过，但"显示真实封面"未达成。
   可选方案：A 维持占位（本轮已做）；B 新增受控封面采集字段并登记 CDN 白名单（属采集变更，需授权）；
   C 由用户提供可验证的封面地址规则。

2. **参考图片未提供**：`docs/assets/` 只有精选集合旧图，本轮无目标参考图，CRE-21 无法逐项核对。
