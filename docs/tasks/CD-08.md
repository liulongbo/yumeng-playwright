## 目标与范围

修复达人详情页两个已确认缺陷，并以巨量星图同一达人、同一统计口径、同一数据时点的展示值为准，保证**采集值 → 标准化存储值 → 前端展示值**三者一致。

### 任务一：创作能力「最新视频表现」下方作品列表封面不显示

- 现状：页面提示「平台未提供封面地址」。
- 预期：作品列表展示与视频正确对应的真实封面；封面缺失时明确说明原因，不用其它作品的封面替代。
- 已知线索：商业能力「优秀传播视频」「优秀种草视频」封面正常。

### 任务二：商业能力「内容数据 → 传播量中位数」与巨量星图不一致

- 对象：达人 ID `6639192346380468227`。
- 现状：巨量星图 `76.6w`，本系统 `1399516`（显示 139.9w）。
- 预期：与平台同口径一致，且**不能靠前端格式化掩盖字段错误**。

包含：

- 任务一：复用既有 `get_sign_image` 签名请求与已登记 CDN 白名单，为作品列表补上「平台原始 key → 已签名外链 → 受控入库 → 授权端点提供」的链路；历史数据用已存 key 回填封面对象（用户 2026-10-16 选定方案 A）。
- 任务二：把「播放量中位数」的读取源从顶层 `spread.play_mid` 修正为 `spread.item_rate_metrics.play_mid`（含同行超越），并保证标准化存储值与展示值一致。

明确不做：

- 不构造未经验证的 CDN 地址，不猜域名，不放宽封面白名单。
- 不用其它作品封面替代缺失封面；缺失即如实标注。
- 不改动 P1/P2 无关模块；不改精选集合既有接口行为；不改其它六项内容数据指标。

## 根因证据（2026-10-16 实测）

### 任务一

| 模块 | 契约请求 | 封面来源 | 结果 |
|---|---|---|---|
| 优秀传播/种草视频 | `author_spread_videos`/`author_shopping_videos` + `cover_signs` | 卡片 `cover_uri` → `get_sign_image` 的 `mainURL` | 正常（613 张已入库） |
| 创作能力最新视频 | 仅 `show_items` | `latest_item_info[].item_cover` = 不透明对象存储 key | 不可渲染 |

只读实测：平台页面自身请求
`/gw/api/fe_common_service/tools/get_sign_image?uri=tos-cn-i-0813c001%2FosvAyCE5GFDA9ggqRvAqFnfAf7NAFqQAlUIpK3&durationTS=86400&format=webp` → `200`，并渲染 `https://p26-star-fe-sign.byteimg.com/tos-cn-i-0813c001/…~tplv-9hvokabxw2-image.webp`（734×978）。该 key 即库内该达人第一条最新视频的 `item_cover`。

参数实测：`?uri=<key>` 单独调用返回 `200` 但 `mainURL` 为 `.jpeg`（`image/jpeg`，不在已登记白名单）；加 `&format=webp` 得到 `.webp` 且落在已登记主机 `p3/p26-star-fe-sign.byteimg.com`。**结论：端点、主机白名单、内容类型白名单、`CoverPipeline`、封面授权端点全部已存在，无需新增 CDN 白名单。**

### 任务二

同一 `spread` 响应含两个不同的播放中位数叶子：

| JSON 路径 | 库内值（该达人最新快照） | 线上同一卡片 | 判定 |
|---|---|---|---|
| `spread.item_rate_metrics.data.play_mid` | `766187` / `9923` | 「播放量中位数 76.6w，优于 99.23% 同类型达人」 | ✅ 正确来源 |
| `spread.play_median`（顶层 `play_mid`） | `1399516` | 线上无对应展示 | ❌ 当前被误用 |

线上逐卡片核对：其余六项均与库内一致（完播率 `2.5%/96.93%`↔`253/9693`，互动率 `3.1%/78.56%`↔`305/7853`，平均时长 `191.1s`↔`19112`，平均点赞 `3.3w`↔`32600`，平均评论 `1,636`↔`1619`，平均转发 `550`↔`549`）；另一张「播放中位数 133.1w」= `conversion.related_video_play_median`（1331347），映射本就正确。

历史分支看起来正确的原因：达人 `7503176021160493065` 在统计窗口内 `item_num = 1`，两个叶子恰好同为 `948480`（94.8w），CD-02 那次线上核对因此把「播放中位数」记为 `time-shift` 而非 `different`，缺陷未被登记。
