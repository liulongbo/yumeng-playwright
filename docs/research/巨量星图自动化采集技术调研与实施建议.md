调研日期：2026-09-28（Asia/Shanghai）。用户已批准实施；实际进展见 [AUTO-01](../tasks/AUTO-01.md)，不得将研究结论当作实施完成。

## 一、结论与证据范围

推荐真实 Chrome + Playwright 持久 profile、页面业务响应采集为主、必要 DOM 补读、已验证网页接口逐项优化、异常人工接管。复用 PostgreSQL 事务、不可变快照、租约、检查点和 Temporal。每天最多 200 位，完整主页指当前账号可访问的全部业务模块、必要标签与展开项、默认统计口径及默认展示作品；不遍历所有历史周期和完整作品库。

官方 API 按用户成本约束排除，不安排申请、询价或接入。付费第三方数据、全量签名逆向、自动人机挑战求解均不是本期交付依赖。该预算选择不等于调研已证明所有官方 API 都高价。

| 证据层级 | 来源 | 能证明什么 |
|---|---|---|
| 代码事实 | Adapter、Observer、Runtime、Engine、Repository、Workflow、Worker、CLI、真实注册表 | 当前执行路径与实现缺口 |
| 项目既有实测 | 真实登录、首页搜索、2 位基础资料落库、权益不足、挑战记录 | 相应小样本已发生或通过 |
| 一手公开资料 | Playwright、Chrome、Android、ModemManager、星图及验证码产品文档 | 通用基础能力与适用限制 |

本报告最初调研阶段没有新增平台采集；批准实施后已经补充同一上下文登录、跨重启会话、真实搜索前两页、主页数据面和挑战定位实测，详见 AUTO-01 证据。短信设备仍未测试且已移出本期。框架支持不等于星图可用，小样本可用不等于生产稳定。95% 无人值守、每账号每周最多一次介入为建议目标，不是观测结果。

## 二、当前方案评估

实际链路：CLI 提交 → Temporal Activity → 单元租约 → 持久 profile Chrome → 应用会话引导 → 搜索 → 主页 → 响应关联／字段解析 → 事务落库 → 快照。

已有基础值得保留：进程锁和单元租约、请求归属校验、字段来源／单位／时间、检查点与幂等写入、浏览器与编排分离。当前已解析页面业务接口的响应，不是纯 DOM 爬虫。

[真实采集证据](../evidence/UNIT-01-real-collection-2026-09-27.md)证明关键词搜索返回 20 候选、2 位 basic 落库、9 字段有状态和来源；没有证明完整主页和多页可用。[DEC-009](../decisions/DEC-009-crawl-strategy-and-anti-bot.md)记录免人工会话复用和文字点选挑战；挑战同轮部分响应成功不代表可以忽略挑战或所有模块均未受限。

| 当前问题 | 事实 | 必须改变的行为 |
|---|---|---|
| 分页只核验至第 2 页 | 页面内复用已验证页 2，页 3+ 与终点未核验 | 继续逐页实证，能力边界不当平台耗尽 |
| 首页限制返回 exhausted=true | Adapter.search 的边界分支 | 明确 SEARCH_CAPABILITY_LIMIT 并保留未耗尽检查点 |
| 完整度只看登记模块 | basic 也可 profile_complete | 业务需求覆盖独立于执行注册表 |
| 主页范围不全 | 商业、画像等尚未核验 | 逐模块核对入口、字段、周期和缺失证据 |
| 挑战检测未登记 | error_selectors 为空 | 分开登录、挑战、权限、额度、网络与契约错误 |
| 登录恢复缺少产品流程 | 现有 CLI 和维护原语 | 登录后自动校验并续跑原任务 |
| 文档保活未完整实现 | 租约心跳不等于平台保活 | 按需会话检查，不默认高频访问 |
| 固定间隔只覆盖部分 UI 动作 | 页面请求可一次触发多个 | 记录实际访问量与耗时，不把 2 秒当平台阈值 |
| 接口优化未实现 | direct_api_enabled: Literal[False] | 按请求验证和启用，不做全局盲开关 |
| 后台维护待开发 | APP/INTAKE/CONSOLE/F10/OPS 卡片待办 | 复用统一领域与采集链路，不另造采集器 |

工作流的周期性检查不等于反复登录：未就绪单元在租约层会被拒绝。需要新增的是会话恢复执行流程。Cookie 未到期不能证明服务端有效；固定间隔、蜂窝出口、保活均没有防封概率证据；挑战原因不能由一次观察归因。

## 三、技术路线调研

### 1. 会话复用

Playwright 支持保存和复用认证状态，认证可能涉及 Cookie、localStorage、IndexedDB 等；单独导出 Cookie 不保证完整重建会话。[官方认证文档](https://playwright.dev/python/docs/auth)。本项目实测表明 profile 可以承载浏览器环境，但当前星图业务会话不能跨 Chrome 重启恢复。仍以受保护业务能力与账号一致性判断有效；人工登录成功后必须在同一上下文交接采集，不能再用 Cookie 存在或维护窗口内成功推断下一个进程可用。

> **2026-09-29 更正**：上句"不能跨 Chrome 重启恢复"已撤回为"未经证实"，原因见本节顶部更正说明。**仍然成立的部分**：不能以 Cookie 存在或维护窗口内成功推断下一个进程可用 —— 判定必须基于受保护业务能力与**账号 ID 精确一致**（原探针缺失了后者，是历史误判来源）。活跃会话能否跨重启复用、可存活多久，见 [SESSION-01](../tasks/SESSION-01.md)。

Chrome 136 起远程调试默认用户目录受到限制，需独立用户数据目录；继续隔离项目 profile，不接管日常浏览器。[Chrome 官方变更](https://developer.chrome.com/blog/remote-debugging-port)。

结论：成熟、改造成本低，主线采用；不承诺永久免登。

### 2. 页面响应采集

Playwright 原生支持 HTTP/HTTPS、XHR/Fetch 监听。[官方网络文档](https://playwright.dev/python/docs/network)。页面负责自身业务参数与加载，采集器关联响应、校验数据并补读 DOM。页面渲染有成本，页面改版仍须维护；现有代码和测试可复用。

结论：当前项目唯一已有真实小样本证明的数据主路径，作为全字段验证基线。

### 3. 网页接口复用

| 路径 | 能力 | 限制 |
|---|---|---|
| 正常页面触发 | 页面执行业务逻辑并产生响应 | 有渲染、导航与模块展开成本 |
| 页面内请求 | 在浏览器环境执行已验证请求 | 普通 fetch 不会自动调用平台业务封装 |
| browser_context.request | 与浏览器共享 Cookie | 不自动执行页面签名或额外令牌注入 |

[Playwright APIRequestContext](https://playwright.dev/python/docs/api/class-apirequestcontext)只保证相应 Cookie 共享能力，不保证任意站点请求成功。[MDN Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)说明凭据、跨域和受限请求头规则。

实验顺序：记录成功请求 → 定位 Cookie/令牌/页面状态/动态参数依赖 → 同账号同达人同周期对比 → 核验身份、值、单位、缺失与错误语义 → 重启及会话更新测试 → 有收益才逐项启用。不能以 HTTP 200 为通过，不保证减少挑战或免消耗账号权益。

结论：值得实验，未经验证继续浏览器路径。不是官方 API，不需要以官方 API 采购为前提。

### 4. 自有短信设备（已移出本期实施）

[Android 短信接口](https://developer.android.com/reference/android/provider/Telephony.Sms.Intents)提供接收广播与权限机制，投递规则、系统及后台运行需实测。[ModemManager 官方维护者说明](https://lists.freedesktop.org/archives/modemmanager-devel/2016-August/003306.html)证明短信枚举和读取有基础能力，联网模块不自动等于支持收码。

安卓需核验权限、后台存活、投递与重连；蜂窝模块需核验 SIM、驱动、编码与重启。未来重启此项时只接入一种已验证设备，统一号码／时间窗／认证请求绑定，旧码、迟到码和重复码不能误用。短信登录和人机挑战是不同环节；当前按用户新指示保留浏览器登录，不接设备。

### 5. 更换框架

[DrissionPage 官方监听文档](https://drissionpage.cn/browser_control/listener/)提供与当前已有能力重叠的网络监听。没有证据证明换框架可以修复分页、完整度、账号权限或降低星图挑战率。

结论：继续 Playwright，出现明确无法解决的缺陷再评估迁移。

### 6. 逆向与挑战

请求参数、业务码、字段、分页和模块关系分析是本期必要工作；前端请求依赖按接口实验需要分析；脱离浏览器复现签名、设备环境与挑战协议不作为本期交付前提。

图像识别成功不等于服务器认可验证。公开验证码产品存在服务端票据核查，例如[腾讯云接口](https://cloud.tencent.com/document/api/1110/36926)；这是一般机制例证，不声称星图采用腾讯实现。[Selenium 文档](https://www.selenium.dev/documentation/test_practices/discouraged/captchas/)将 CAPTCHA 列为不适合普通测试自动化的场景，测试环境建议不能直接用于第三方平台。

结论：不把“旧规范禁止”当作技术不可行的证明，也不把未经验证的求解成功率当生产能力。优先降低正常流程人工工作，挑战独立分类并人工接管。

### 7. 账号权益

[星图客户权益说明](https://www.xingtu.cn/help-center/demander/109174)将查看资料、头部达人、导出等分列。公开说明较早，当前权限和数量以本账号权益中心核验；不采用第三方日额度数字作为承诺。[名单导出](https://www.xingtu.cn/help-center/demander/120115)要求至少 L3且未证明覆盖全主页，不作为本期主路径。

结论：200 位／天不仅受程序吞吐影响。权限不足不能通过登录或换请求方式解决，需明确报告缺口。

## 四、确定的改造方案

流程：需求校验 → 持久排队 → 浏览器宿主持有单元租约并检查会话 → 有效即采集／失效在当前浏览器进入登录维护 → 校验账号、受保护能力和线路 → 原子切换维护模式为采集模式并更新 session_version → 同一上下文搜索分页与采集 → 事务、检查点、快照 → 完整度与缺口展示。浏览器关闭或租约失效后单元回到需要登录／隔离状态，不假定 profile 可恢复业务会话。

P0：搜索停止语义、独立需求覆盖、分页与字段、错误分类、访问量和耗时观测。

P1：新增有界浏览器宿主，使 Chrome 登录后的校验、维护独占、`maintenance → collect` 原子交接、Temporal 幂等唤醒和原任务续跑发生在同一上下文。人工挑战同样保留当前上下文；维护到期撤销入口，任务仍等待，不能假设登录态或挑战票据可迁移。自动短信收码已排除。

P2：三个代表性网页接口实验、减少经证明无必要的重复操作、受控回退；挑战／权限拒绝不换路径绕过。搜索分页的页面内请求已验证到第 2 页并设硬边界。当前只需要有空闲超时、租约和单元隔离的浏览器宿主，不扩张为无边界的多账号常驻服务，也不采用代理轮换。

接口变化：搜索停止原因；任务需求版本及覆盖；会话明确状态；逐请求执行方式与证据。业务字段要求不能从实际注册模块反推。新增数据采用向后兼容字段；历史快照不修改，旧任务标明旧覆盖语义。工作流历史须兼容。

## 五、实施顺序与交付门槛

| 阶段 | 工作 | 产出／验收 |
|---|---|---|
| 一 | 卡片和边界修订；停止语义、覆盖、异常、指标；账号权益核验 | 基线、字段清单、真实缺口与代码回归 |
| 二 | 完整主页和分页，5 位样本、20 位任务及跨页场景 | 页面与数据库逐字段一致，未执行不作空数据 |
| 三 | 同一浏览器上下文内的维护到采集交接（不含收码设备） | 人工正常登录后不关闭上下文，原任务幂等续跑；关闭后的状态由当前进程结构化 SessionHealth 决定，不能仅因关闭回到待登录（2026-09-29 DEC-013 更正） |
| 四 | 搜索、basic、一个有权限非基础模块的接口实验 | 同条件等价、重启／会话更新／线路测试，有收益才启用 |
| 五 | APP/INTAKE/CONSOLE/F10/OPS 后台集成 | 同一采集器、维护互斥、容量与稳定性证据 |

容量按 20 位 → 逐步最多 200 位／天 → 连续 7 天。8 小时 200 位的平均预算为每位 144 秒，只是计算，不是平台频率许可。出现挑战或明确限制停止提升，不为数量盲重试。

验收分别统计：无人值守完成任务／全部有效提交；字段取得／无数据／无权限／失败／未执行；人工次数／原因／时长；每位耗时／业务请求量／重试与恢复。无权限作为明确缺口，不算已取得。95% 与每周一次为目标；7 天不能证明长期封号概率，不以缩减字段提高指标。

本报告完成不代表代码、实机或生产完成；实施记录与真实测试见 AUTO-01 及关联证据。上线、短信设备（若未来恢复）、全字段、接口等价性和持续观察各自验收。
