# DEC-011：自有账号自动化优化及认证边界修订

日期：2026-09-28。状态：用户已批准；按 AUTO-01 分阶段实施和实证。

最新用户修订：自动化短信先不做，继续 Chrome 短信／账号密码入口登录。本期移除短信设备、自动收码与代填验证码，保留会话复用、登录校验和原任务恢复；以下短信可行性结论仅为未来备选。

本决策取代 DEC-010 中“短信码自动读取不可实现／一律属于绕过”的结论；保留该文件作为历史，不删除原验收记录。正常使用自有账号、自有短信设备接收本次登录验证码可开发验证；不等同于自动通过人机挑战。旧开发规范与技术方案中将所有验证码统一交给人工的条款，以本次用户批准的明确变更为准。

推荐保留 Chrome + Playwright 持久 profile、页面响应采集、必要 DOM、PostgreSQL 与 Temporal。新增业务需求覆盖、准确停止原因、错误分类、会话恢复与人工登录后续跑。已验证网页接口按请求逐项实验，验证前关闭。官方 API、第三方付费数据、全量签名逆向和自动挑战求解不在本期。

不承诺固定间隔、蜂窝出口或保活能防封；Cookie 到期不等于服务端有效。95% 无人值守与每周一次介入是建议目标，不是实测结果。账号权益、完整数据、接口等价性及 7 天观察各自有证据后才能验收。

执行卡片：[AUTO-01](../tasks/AUTO-01.md)。调研与分阶段方案：[研究报告](../research/巨量星图自动化采集技术调研与实施建议.md)。

## 2026-09-28 实施证据修订

同一 Chrome 上下文内人工登录后，账号可进入客户后台和达人广场；关闭 Chrome 再以同一 profile 启动时，受保护业务会话不能恢复。由此撤销“维护窗口关闭后，独立 Worker 重新打开 profile 即可续跑”的实现假设。登录维护与采集必须由同一浏览器宿主持有同一上下文，通过租约保护的 `maintenance → collect` 状态切换完成交接；浏览器关闭时回到 `NEEDS_LOGIN`，关闭未确认时进入隔离。

> **2026-09-29 更正**：本段"受保护业务会话**不能恢复**"的结论**证据不足，现予撤回**，改为"未经证实"。原证据自述无法区分"用户新登录"与"既有会话被接受"，且当时的探针只验证受保护元素可见、**从未比对账号 ID**，故结论可能是测量假象；用户日常 Chrome 实测可 7-8 天免登录，而项目独立 profile 约 45 分钟失效，方向相反。真实存活时长改由 [SESSION-01](../tasks/SESSION-01.md) 独立核验。
>
> **本段中仍然有效的部分**：撤销"维护窗口关闭后由独立 Worker 重开 profile 续跑"这一**实现**假设依然成立（对象不跨进程传递仍是正确工程约束）；"登录维护与采集必须由同一浏览器宿主持有同一上下文、经 `maintenance → collect` 原子交接"**保持不变**。关闭结果不再由布尔值决定；当前状态机见 [DEC-013](DEC-013-structured-session-and-scoped-contract-health.md)。
