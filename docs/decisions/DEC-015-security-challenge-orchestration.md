# DEC-015：安全验证托管、稳定恢复与有界部分完成

> 日期：2026-10-10。状态：后端已实施，产品页面与真实平台验收待完成。关联任务：[CHALLENGE-01](../tasks/CHALLENGE-01.md)。

## 问题

真实 M3 运行在 2 位有效达人、159 个关联请求中触发 5 次安全验证；五次 `collect → maintenance → collect` 仅间隔约 69–84ms。旧 `wait_for_manual_clearance` 只判断挑战元素当下不可见、保护页可见和账号可读，页面闪烁即可造成假恢复；Worker 的同 Activity 循环又没有达人级或任务级上限，因而继续放大请求。

## 选择

1. 新增独立 `ChallengeHandler`，只负责检测后的状态、只读等待、稳定确认、计数、恢复和终止；不点击或操作验证控件。
2. 任务使用 `WAITING_FOR_VERIFICATION`，执行单元正常释放时使用 `NEEDS_VERIFICATION`；安全验证不再伪装成登录等待。
3. 恢复要求挑战连续不可见 5 秒，同时受保护页面可见、账号可读且与绑定账号一致；任何闪烁重置窗口。登录页、错误账号和未知安全状态均不继续采集。
4. 同一达人最多成功恢复 1 次，同一根任务最多成功恢复 2 次，单次等待最长 15 分钟；恢复后冷却 60 秒，达人间隔至少 15 秒。达到限制后发布已持久结果并以明确原因部分完成。
5. 等待期间保留 BrowserHost、Context、Page、profile、租约和心跳，但不执行导航、搜索、模块、精选集合或封面业务动作。一次真实恢复只通过既有原子 promotion 增加一次 `session_version`。
6. 检查点追加带默认值的挑战与访问计数，保持 `checkpoint.v1` 和旧 JSON 可读；根任务与执行单元状态列均为文本，不新增迁移。
7. 恢复前检查已有结果：完整模块继续复用；完整精选集合在 Adapter 发起重载前即跳过；已存封面随完整集合一起复用。

## 合规边界

不实现滑块破解、鼠标轨迹模拟、OCR/打码、隐身驱动、随机 UA、代理/账号轮换、签名逆向或未经官方确认的私有接口。官方开放能力只有在正式权限、文档、频率限制和字段等价性验证完成后才可逐模块替代网页路径；当前运行时不依赖任何推测 API。

## 兼容与回滚

- Temporal Activity 名称与 Workflow 类型不变；新增 `waiting-for-verification-explicit-wake-v1` patch 保护历史重放。
- 所有新增检查点字段均有零值/空值默认值；旧任务无需迁移。
- 新状态通过既有文本列持久化；旧版本前端未识别 `WAITING_FOR_VERIFICATION`，产品页面接入完成前不得宣称产品闭环完成。
- 可回滚应用代码而不回滚数据；旧代码读取检查点时 Pydantic 的 `extra=forbid` 不兼容新增字段，因此回滚前必须先验证读取兼容或保留本版本读取层。

## 验证门槛

离线必须覆盖挑战闪烁、稳定窗口、超时、账号不一致、旧检查点、达人/任务上限、执行单元释放、API 摘要和精选集合提前跳过。真实平台只允许自然触发的小样本验收，不主动制造风控；必须证明等待期零业务操作、稳定窗口不少于 5 秒、恢复后检查点复用及终态请求停止。
