# DEC-016：受限的人工身份确认用于会话快照

> 日期：2026-10-13。关联：[SESSION-01](../tasks/SESSION-01.md)、[DEC-013](DEC-013-structured-session-and-scoped-contract-health.md)。

## 待解决的问题

执行单元 `unit-local-mac-02` 已进入巨量星图受保护业务页，但平台当前 DOM、账户管理页和唯一同源 iframe 均不再提供可读的子账号 ID。原账号定位器失效，导致系统无法在不降低账号错配保护的前提下导出已登录会话的私有快照。

用户于 2026-10-13 明确确认该登录身份只有一个子账号 `ID: 1807978499337419`，并授权人工确认作为受控兜底。

## 选择

为**本机开发单元**增加配置化 `manual_identity_attestation`：记录账号、操作者、原因、批准时间和截止时间。有效期最多 31 天；当前授权为 30 天。它只有在以下条件同时成立时才把会话判为 `VALID` 并允许导出私有 `storage-state`：

- 当前页面已命中注册的受保护业务页标记；
- 未命中注册的登录页或安全挑战页；
- 账号定位器缺失、不可读或为空；
- 确认的账号与单元的 `expected_account_id` 精确一致。

若定位器读到不同账号，仍返回 `ACCOUNT_MISMATCH`；登录页和挑战页也始终优先于人工确认。配置过期、账号不一致、非 `local_development` 单元，均拒绝加载。会话 Cookie 只写入项目私有运行目录（目录 `0700`、文件 `0600`），不会发送至前端、日志或证据。

## 未采用方案

| 方案 | 原因 |
|---|---|
| 仅凭受保护页可见就认定已登录 | 不能防止账号切换，风险不可接受。 |
| 复制 Chrome Cookie 数据库或删除 Singleton 锁 | 可能破坏正在使用的 profile，且绕开 macOS Keychain。 |
| 永久关闭账号核验 | 无到期、无审计，扩大错误账号采集风险。 |
| 每次任务都要求重新登录 | 与已验证的持久 profile / storage-state 机制冲突，且不能解决平台 DOM 缺失。 |

## 兼容性、回滚与限制

没有该配置的单元保持原有严格账号定位逻辑；删除该配置块或到期后立即恢复 `INDETERMINATE`。本选择不承诺平台服务端会话的寿命：平台主动失效、登录页、挑战页或可读身份不匹配时仍必须重新登录或人工处理。

## 最小验证

新增契约测试覆盖：仅受保护页且账号定位器不可读时可使用确认；可读错误账号、登录页及挑战页必定拒绝兜底。配置测试覆盖本地开发限制、账号精确匹配和 31 天上限。真实冷启动诊断及快照权限结果记录在 SESSION-01。
